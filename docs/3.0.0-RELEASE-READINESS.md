# v3.0.0 candidate — 22 October 2026

Status: prepared for local and CI verification. Do not publish a release tag until actual controller input is verified. Public downloads remain v2.2.0.

## Completed

- Version metadata prepared as 3.0.0, preserving bundle ID and existing licence storage.
- Reproduced a live DualSense handle being invalidated by available_count(): six axes became zero after the query. Discovery, rescan and closing a slot now preserve the shared SDL subsystem.
- Readers bind to device instance IDs so another controller unplugging does not redirect or disable them. Background input remains enabled when Qt or a DAW owns focus.
- Connect shows detected devices, explicit single-device selection and the Pro two-controller action. Status shows each slot's phase, output route, channel, sent-message count and error.
- A missing controller reconnects independently; changing the configured mode never replaces a running worker. Failed starts release their reader and terminate the worker thread.
- Calibration start/result are non-modal toasts, with a highlighted initial instruction. Manual recalibration is consumed by the worker's poll loop rather than waiting forever on a queued Qt slot.
- Console/MIDI share one resizable bottom row, capped at half the window. Native-window geometry checks cover the cap and expansion.
- Input testing is explicit in Status and receives raw input events.
- Manual CI builds use the package version in archive names. Publishing remains guarded to tag refs only; a dispatch on main cannot publish a GitHub Release or storefront manifest.
- A user recording showed Xbox input and outgoing MIDI working, and exposed a missing Ableton Remote Script in the packaged app. The build now bundles the entire connector template tree and the exporter checks its source before replacing a destination.

## Verification and remaining gates

- Focused controller-lifecycle, native-window, SDL profile and paint checks pass. Native UI probes run in their own process using the production launcher's shutdown convention.
- Local PyInstaller macOS build launches and produces its smoke screenshot. Its plist reports version 3.0.0, the existing bundle ID, and packaged Phosphor icons. Ad-hoc signature verification passes.
- The broad pytest run executes over 7,300 passing assertions, but the normal interpreter teardown exits with SIGSEGV on this machine. The untouched baseline run before these changes had the same exit 139. Do not describe the standard full-suite command as green.
- Existing GitHub lint is red with thousands of prior findings (4,029 on the last pushed UI commit). This task does not mass-rewrite unrelated source or hide the job.
- The recording verifies Xbox visuals and the app's outgoing MIDI activity; it does not show Ableton receiving that MIDI or PS5 input. Last direct SDL probe listed zero controllers. The earlier app handover also left Xbox button indices unverified. Before a public release, verify actual notes/CC and visualization from PS5 over Bluetooth and USB, then both controllers together, and unplug/reconnect either while the other keeps working. A compiled app or synthetic smoke test does not establish those hardware results.
