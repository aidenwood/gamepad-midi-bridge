On-Site Field Manual

PS5 Controller → MIDI Bridge

DualSense over Bluetooth (via long-range USB dongle), translated through DS4Windows and a Python bridge into a loopMIDI virtual port that Resolume Arena listens to. Cold-start procedure, debugging recipes, and what to do when nothing is responding minutes before doors.

Section 01

The chain — what's going on

Six components in series. If any one is dead, the rest are useless. Knowing what each does makes debugging much faster.

Signal flow
  [DualSense]
       │  Bluetooth (via long-range USB dongle)
       ↓
  [Windows Bluetooth stack]
       │  raw HID input
       ↓
  [DS4Windows]           ←─ translates DualSense to virtual Xbox 360 controller
       │  XInput
       ↓
  [ps5_bridge.py]        ←─ Python script reading gamepad, writing MIDI
       │  MIDI messages
       ↓
  [loopMIDI port "ps5-bridge"]   ←─ virtual MIDI cable inside Windows
       │  MIDI messages
       ↓
  [Resolume Arena]       ←─ listens to ps5-bridge as MIDI input device

Each link has a sign it's working:

LinkHealthy signal
ControllerLight bar on (solid colour, not blinking)
Windows BluetoothController shows "Connected" (not just "Paired") in BT settings
DS4WindowsController listed with green icon; virtual Xbox controller appears in joy.cpl
Bridge scriptPowerShell window shows "Bridge running. Press Ctrl+C to stop."
loopMIDIBytes counter next to ps5-bridge ticks up when you press buttons
Resolumeps5-bridge enabled in Preferences → MIDI; mapped buttons fire parameters
Debug by walking the chain

When something doesn't work, don't randomly poke at things. Start from the symptom (Resolume not responding) and walk backwards through the chain checking each link's healthy signal. Stop at the first broken link — that's where the problem is.

Section 02

Cold-start sequence

Exact order to bring everything up from off. Doing this out of order is the #1 cause of "it's not working" panic.

  1. Plug in the USB Bluetooth dongle. Make sure it's the dongle, not internal Bluetooth, that Windows is using. If you have internal Bluetooth enabled it can grab the controller instead of the dongle and you'll get garbage range.

    Verify in Device Manager → Bluetooth — the dongle should be present and active. Internal Bluetooth should ideally be disabled (right-click → Disable device).

  2. Power on the controller. Hold PS button until light bar comes on. Wait 5–10 seconds for it to auto-connect to Windows.

    Confirm in Windows Bluetooth panel: should say "Connected", not just "Paired". If only paired, press PS button again to wake it.

  3. Launch DS4Windows. Wait until the Controllers tab shows your DualSense with a green icon and "Connected" status.

    If the controller doesn't appear in DS4Windows, toggle it off (hold PS button 10s) and back on. If still missing, restart DS4Windows.

  4. Verify in joy.cpl. Press Win+R, type joy.cpl, Enter. You should see "Xbox 360 Controller for Windows" in the list (this is the virtual controller DS4Windows creates). Open it, wiggle sticks, confirm buttons register on the test screen.

    You will not see "DualSense" or "Wireless Controller" if HidHide is set up properly — that's correct. The virtual Xbox controller is what every app will see.

  5. Launch loopMIDI. The window opens or it appears in the system tray.

    Confirm the ps5-bridge port is in the list. If it isn't — type ps5-bridge in the "New port-name" field and click the + button to recreate it.

  6. Run the bridge script. Open PowerShell. Run:

    cd ~\Desktop python ps5_bridge.py

    You should see a startup block listing the joystick (Xbox 360 Controller for Windows), the MIDI ports it found, and which port it opened. Final line:

    Bridge running. Press Ctrl+C to stop.

    Leave this PowerShell window open and visible — it's your status display. Errors will show up here in real time.

  7. Launch Resolume Arena. Open it as normal.

    Go to Arena → Preferences → MIDI. Confirm ps5-bridge is in the MIDI input device list and the "Use MIDI Input" checkbox is ticked. Close preferences.

  8. Verify the full chain with the sanity test below. Don't trust it until you've actually pressed a button and seen something happen end to end.

Shutdown order doesn't matter much

You can close everything in any order. But on cold start, the order above matters because each layer expects the one below it to already exist. If you launch the bridge script before DS4Windows is running, the script errors out with "No joystick detected" and exits.

Section 03

Sanity test — confirm the whole chain

A 30-second check to run every show before anyone arrives.

  1. Press the Cross (X) button. Watch loopMIDI's window — the bytes counter next to ps5-bridge should tick up by a few bytes. That proves controller → DS4Windows → script → loopMIDI is all working.

  2. Press a trigger (L2 or R2). Counter should climb continuously while held. That proves analog axes are flowing.

  3. In Resolume, enter MIDI learn mode: Shortcuts → Edit MIDI.

  4. Click an empty clip slot. Press Cross. Resolume should show a MIDI assignment (a small label like "C3" or "Note 60") on that clip. Exit MIDI learn mode.

  5. Press Cross outside of learn mode. The clip you just mapped should trigger. That proves loopMIDI → Resolume is working and the mapping persisted.

If all five steps work, the whole chain is solid. If any step fails, see troubleshooting.

Section 04

Two-script workflow

Two bridge scripts live on the Desktop. They do the same thing but with different stick behaviour, for different situations.

ScriptSticksWhen to use
ps5_bridge.py Active (with deadzone) Normal showtime use — full controller capability
ps5_mapper_bridge.py Disabled entirely Mapping new parameters in Resolume's MIDI learn mode, or anytime stick drift is causing trouble

Why two scripts?

The DualSense's analog sticks have measurable drift — even at rest, they don't sit at perfectly zero, so they send continuous tiny CC value changes. In normal use this is fine (the deadzone filter swallows it). But during MIDI learn mode in Resolume, those drift values can hijack the mapping: you click a parameter intending to bind it to a button, and a stick-drift CC gets captured instead.

The mapper variant skips stick reading entirely, so the only MIDI flowing during learn mode is what you explicitly press. Once you've mapped everything you need, switch back to the full version.

Switching between them

  1. Stop the current script. Press Ctrl+C in its PowerShell window. The script exits cleanly, releasing the MIDI port and the controller.

  2. Run the other one in the same window (or a new one):

    python ps5_mapper_bridge.py

    or

    python ps5_bridge.py

  3. That's it. Resolume's MIDI mappings are unaffected — they live in the Resolume project file, not in the script.

If sticks are useless to you anyway

If you find you never actually use the sticks during shows (which is common — most VJs use buttons and triggers far more than sticks), just use ps5_mapper_bridge.py as your everyday bridge. The drift problem goes away permanently and you don't have to think about which script is running.

Section 05

Troubleshooting

Symptom → likely cause → fix. Click any heading to expand. Walk the chain — start from the symptom and work backwards toward the controller.

Script-launch failures

Script won't start — "No joystick detected"

The script can't see any gamepad. Either the controller isn't actually connected or DS4Windows isn't running.

  1. Check the controller's light bar — is it on? If not, press PS button.
  2. Check Windows Bluetooth panel — does it say "Connected" or just "Paired"? Paired ≠ connected.
  3. Check DS4Windows is running and shows the controller with a green icon.
  4. Open joy.cpl — does "Xbox 360 Controller for Windows" appear? If not, DS4Windows isn't creating the virtual controller. Restart DS4Windows.
  5. Re-run the script after fixing.
Script won't start — "No port matching 'ps5-bridge' found"

The loopMIDI port doesn't exist or has a different name.

  1. Open loopMIDI. Is it running? Is the ps5-bridge port in the list?
  2. If missing, type ps5-bridge in the "New port-name" field and click +.
  3. Re-run the script.
  4. If you've renamed the port to something else, open the script in Notepad and change MIDI_PORT_NAME at the top to match.
"ModuleNotFoundError: No module named 'pygame'" (or rtmidi)

The Python packages aren't installed in the Python environment the script is running in. Usually because you installed Python twice and pip went to a different copy.

  1. In PowerShell, run: pip install pygame python-rtmidi
  2. If pip isn't recognised: py -m pip install pygame python-rtmidi
  3. Check which Python you're using: python --version and where python. If multiple paths show up, you have multiple installs.
  4. Easiest fix in that case: uninstall the older Python via Settings → Apps, keep only one, reinstall the packages.
"python" not recognised in PowerShell at all

Python was installed but not added to PATH.

  1. Try py instead — Windows ships a Python launcher that often works when python doesn't: py ps5_bridge.py
  2. If neither works, reinstall Python and explicitly tick "Add Python to PATH" during install.
  3. After reinstall, close and reopen all PowerShell windows — PATH changes don't apply to existing sessions.

Chain mid-flow failures

Script runs but loopMIDI bytes counter doesn't move

Script started but isn't reaching loopMIDI.

  1. Read the script's startup output — which MIDI port did it open? Should match ps5-bridge.
  2. If it opened a different port (e.g. "Microsoft GS Wavetable Synth"), the port name lookup failed. Quit the script, fix loopMIDI port naming, restart.
  3. If you have multiple loopMIDI ports with similar names, the script picks the first match — rename other ports or be more specific with MIDI_PORT_NAME.
  4. Check the controller is actually doing something — set DIAGNOSTIC_MODE = True at the top of the script, re-run, and you'll see input prints in PowerShell.
loopMIDI counter ticks but Resolume doesn't respond

MIDI reaches loopMIDI but Resolume isn't reading it.

  1. In Resolume: Preferences → MIDI. Is ps5-bridge in the list?
  2. Is the "Use MIDI Input" checkbox actually ticked? Visible ≠ enabled — must be checked.
  3. Did you exit MIDI learn mode after mapping? Mappings won't fire until you exit learn mode.
  4. Try MIDI-learning a fresh parameter — sometimes old mappings get orphaned.
  5. Restart Resolume if all else fails. Mappings are saved in the composition file and survive a restart.
Wrong buttons trigger wrong things

Button indices on your specific controller/driver combo don't match the script's defaults.

  1. Stop the script (Ctrl+C in PowerShell).
  2. Open the script in any text editor. Set DIAGNOSTIC_MODE = True near the top.
  3. Re-run. PowerShell will print every input change live: button 0 DOWN -> note 60, etc.
  4. Press each button on the controller and write down which index it reports.
  5. Edit the BUTTON_NOTES dictionary to match the indices you observed.
  6. Set DIAGNOSTIC_MODE = False, re-run.

Hardware & connection issues

Sticks send constant CC traffic when at rest (drift / jitter)

The stick's centred position isn't perfectly zero — it floats slightly, causing CC values to bounce.

  1. Quick fix: switch to ps5_mapper_bridge.py — sticks disabled entirely.
  2. If you want sticks active but less twitchy, open the full script. Find DEADZONE = 0.08 near the top. Increase to 0.15 or 0.20. Re-run.
  3. If still jittery at 0.25+, the controller's sticks are physically worn. Confirm on another machine, then either replace the controller or live with the mapper variant.
Controller works for a while then dies / drops out

Almost always Bluetooth range or interference. Less commonly, the controller's battery is dying.

  1. Move closer to the dongle and see if the connection re-establishes.
  2. Check the controller's battery — hold PS button, look at the on-screen popup. Below 20% is worth charging or swapping.
  3. If you're operating at the back of a room and the dongle is on stage, you're at the edge of range. Consider running a USB extension from the Windows machine to a dongle nearer to you.
  4. 2.4GHz Wi-Fi can interfere with Bluetooth. Crowded RF environments degrade range.
  5. Plug controller in via USB-C as fallback (see below). Wired DualSense works fine and DS4Windows handles the switch transparently.
Bluetooth connection refuses to come back

The controller is on, but Windows won't pair or reconnect.

  1. In Windows Bluetooth settings, click the PS5 entry → Remove device.
  2. On the controller, hold PS + Create simultaneously for ~3 seconds. Light bar should flash rapidly in blue. Rapid = pairing mode. Slow pulse = on but not pairing.
  3. In Windows: Add Bluetooth device → Bluetooth. Pick "Wireless Controller" from the list.
  4. Once paired, restart DS4Windows so it re-grabs the new connection.
USB-C wired fallback procedure

If Bluetooth is completely broken (interference, dongle failure, controller refusing to pair), you can fall back to a wired connection.

  1. Plug a USB-C cable from the controller into the Windows machine.
  2. DS4Windows should pick it up automatically as a wired DualSense.
  3. The controller will work identically — buttons, triggers, sticks all the same. Just tethered.
  4. If DS4Windows shows both wired and Bluetooth at once, disconnect Bluetooth in Windows to avoid double-input.
  5. Plan accordingly — wired means you operate from within cable length of the machine. Have a long USB-C cable in the kit.

Bonus: wired latency is roughly half of Bluetooth. If you ever need ultra-tight rhythmic triggering, USB-C beats wireless.

Driver & system issues

DS4Windows says "Controller is in exclusive mode" or won't connect

Another app has grabbed the controller's raw HID and won't let DS4Windows access it. Common culprits: Steam (especially Steam Input), open games, Discord, controller config utilities running in background.

  1. Quit Steam entirely — including the system tray icon. Steam grabs controllers aggressively.
  2. Close any games or controller-mapping apps.
  3. In DS4Windows: Settings → ensure "Hide DS4 Controller" is enabled.
  4. Toggle controller off (hold PS button 10s) and on, let DS4Windows reclaim it.
  5. If still stuck, reboot Windows. Sometimes the HID exclusivity gets wedged and only a fresh boot clears it.
DS4Windows complains about ViGEmBus missing

ViGEmBus is the virtual gamepad driver DS4Windows uses to create the Xbox 360 controller. Without it, no virtual controller appears.

  1. In DS4Windows, click the prompt to install ViGEmBus. It'll download and install automatically.
  2. If that fails: download manually from github.com/ViGEm/ViGEmBus/releases. Install the latest .msi.
  3. Reboot Windows after install. Driver registration sometimes needs it.
  4. Re-launch DS4Windows. The "Xbox 360 Controller for Windows" should now appear in joy.cpl when the controller is connected.
joy.cpl shows both DualSense AND Xbox 360 Controller

HidHide isn't running or isn't configured to hide the real controller. This usually causes "double-input" issues where buttons fire twice.

  1. In DS4Windows: Settings → Device → enable "Hide DS4 Controller".
  2. If that doesn't help, install HidHide separately from github.com/nefarius/HidHide/releases.
  3. After install, open HidHide config and add the DualSense to the "hidden devices" list.
  4. Reboot. After reboot, joy.cpl should only show the Xbox virtual controller.

Mid-show recovery

I accidentally closed the PowerShell window / script

No need to restart anything else. The bridge is the only piece that needs to come back up.

  1. Open PowerShell.
  2. cd ~\Desktop
  3. python ps5_bridge.py
  4. Resolume keeps its MIDI mappings — they don't depend on the script being running, just on loopMIDI staying alive (which it does).
I accidentally closed loopMIDI

This is worse — when loopMIDI closes, the virtual port disappears. Resolume loses its MIDI input device. The bridge script either crashes or sits there sending into the void.

  1. Restart loopMIDI from the system tray or Start menu.
  2. Confirm the ps5-bridge port exists. Recreate it if not.
  3. Stop the bridge script (Ctrl+C) if it's still running, then restart it.
  4. In Resolume: Preferences → MIDI. Re-enable the ps5-bridge input (it'll be unticked because the device went away).
  5. Test with the sanity check — mapped buttons should fire normally.
Section 06

Emergency recovery

Five minutes to doors and nothing's working. The minimum-viable fix path.

Five-Minute Fix

If you don't have time to debug, just nuke and restart everything in this exact order. Most problems are state corruption that a clean restart resolves.

  1. Close everything related. Quit PowerShell (Ctrl+C in script window then close). Quit DS4Windows (right-click tray icon → Exit). Quit loopMIDI (tray icon → Exit). Quit Resolume.

  2. Power-cycle the controller. Hold PS button for 10 seconds until light bar goes off. Wait 5 seconds.

  3. Confirm the dongle is seated. If you've been bumping the machine, USB connections come loose. Unplug and replug the Bluetooth dongle.

  4. Press PS button to turn controller back on. Wait until Windows shows it as connected in Bluetooth panel.

  5. Launch in order: DS4Windows → loopMIDI → bridge script (PowerShell) → Resolume.

  6. 30-second sanity test. Press Cross — clip fires. Done.

If even that doesn't work

Fall back to USB-C wired. Plug a USB-C cable from controller to machine, restart DS4Windows. Bluetooth is the most failure-prone link in the chain — wired bypasses it entirely. You lose range but gain reliability. Have a long USB-C cable in the bag for exactly this scenario.

If THAT doesn't work either

You're operating without the controller for this show. Resolume can still be controlled by mouse and keyboard. Pre-mapped MIDI shortcuts via the keyboard still fire (Shortcuts → Edit Keyboard). Plan a fallback set you can run from QWERTY before show day so this isn't catastrophic.

Section 07

Performance & latency

What's normal, what's not, and what to do if things feel sluggish.

Expected latency

ConnectionEnd-to-end latency (button press → Resolume action)
Bluetooth (good signal)~25–40 ms
Bluetooth (weak signal / interference)50–150 ms, occasional dropouts
USB-C wired~10–15 ms

The script's poll rate is 100 Hz by default (set by POLL_HZ = 100), adding up to 10 ms of internal latency on its own. For most VJ use this is invisible; for tight rhythmic triggering on hi-hats or fast cuts, you'll notice the Bluetooth path's variability.

If it feels laggy

  1. Check controller signal. Bluetooth dropouts cause "stuck on" notes or missed presses. Move closer to the dongle as a test.
  2. Check CPU. If Resolume is rendering at low FPS, MIDI handling can lag too. Open Task Manager — if Resolume is pegged at 100% CPU, you have bigger problems than MIDI latency.
  3. Increase POLL_HZ. Edit the script, set POLL_HZ = 200. Halves the internal latency. Costs slightly more CPU.
  4. Switch to wired. The single biggest latency improvement available.

If you see "stuck" notes

Symptom: a parameter stays activated as if a button is held down, even after you release it. Cause: a Note-Off message got dropped (usually from Bluetooth packet loss) and Resolume still thinks the button is held.

  1. Press and release the same button — usually a fresh Note-Off arrives and unsticks it.
  2. If the parameter is stuck and won't release: in Resolume, enter MIDI learn mode briefly and exit — this resets some internal state.
  3. Worst case: stop and restart the bridge script. The script's cleanup code sends Note-Off for any held notes on exit, which clears stuck state.
